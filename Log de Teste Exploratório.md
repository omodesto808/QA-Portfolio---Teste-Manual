**Log de Teste Exploratório**

Ao abrir a página do SauceDemo, somos recebidos por uma infinidade de usuários possíveis. Sendo assim, vou usar os 6 usuários diferentes fornecidos como minha Massa de Teste.

Começando com o usuário principal "standard\_user", na página inicial/catálogo, já é fácil perceber algo estranho. A exibição dos itens está boa e segue um padrão fácil de navegar, mas o nome exibido em um dos itens parece um placeholder, algo que não deveria estar visível no produto final: a camiseta de manga longa exibe o nome "Test.allTheThings() T-Shirt (Red)". Também vejo algo parecido na descrição da mochila, com o texto "carry.allTheThings()" no início da descrição. Já que estou no catálogo, testei os Filtros, e tudo funcionou bem. Ao entrar na página do produto, consegui ver facilmente a descrição completa dos itens e adicioná-los ou removê-los do carrinho sem problemas. No carrinho, o valor é calculado corretamente, e também conseguimos remover itens, o que é refletido corretamente no valor final do carrinho. Indo para o checkout, porém, os campos First Name e Last Name aceitam informações inválidas, como números ou caracteres especiais, e o mesmo acontece com o campo Zip Code quando preenchido com letras, por exemplo. Isso é um problema realmente grande, considerando a entrega desses produtos — a página não exibe nenhuma mensagem de erro, simplesmente segue para o resumo dos itens adicionados ao carrinho e para o checkout. Deixando isso de lado, o pedido é concluído, e tecnicamente conseguimos finalizar um pedido sem problemas maiores. Ainda assim, existem alguns erros importantes que precisam ser corrigidos. Na página final da jornada, ficamos com uma mensagem "Thank You for your order" e opções para gerar um PDF do pedido ou voltar para a Home Page.

Por enquanto, é isso para o Standard User. Seguindo para um novo usuário, também podemos testar a funcionalidade de logout, que funciona perfeitamente.

Ao tentar fazer login com o "locked\_out\_user" como minha Massa de Teste, o que acontece é o esperado: já que o nome sugere que ele deve ter sido bloqueado de usar o site, o site nega toda tentativa de login com esse usuário.

Passando para o "problem\_user", na Home Page somos recebidos por várias imagens de cachorro substituindo a imagem de cada item no catálogo. Além disso, ao tentar adicionar itens ao carrinho, você verá que apenas os itens "SauceLabs Backpack", "SauceLabs Bike Light" e "SauceLabs Onesie" têm o botão "Add to cart" clicável, e depois de adicioná-los ao carrinho, não é possível removê-los clicando no ícone "Remove" — apenas indo até o carrinho. Seguindo a mesma linha de exploração, clicar em qualquer ícone de item redireciona para a página de um produto completamente diferente, e no caso da "SauceLabs Fleece Jacket", o item nem pode ser encontrado (embora você seja redirecionado para a página dele ao clicar na "SauceLabs Backpack"), e é possível até adicionar o "Item Not Found" ao carrinho, mas ele não aparece no carrinho final. Passando para a função de ordenação, ela também não funciona como deveria — nada acontece ao selecionar um filtro. Indo para o carrinho, os três itens que adicionamos com sucesso aparecem no carrinho final, mas ao avançarmos para a página de Checkout, conseguimos preencher os campos First Name e Zip Code (também com caracteres especiais e números, assim como aconteceu com o standard user), mas o Last Name não pode ser preenchido — cada caractere digitado vai para o campo First Name, então não conseguimos concluir o checkout de forma alguma.

Com o "performance\_glitch\_user", mais uma vez o nome fala por si só, e ficamos com um usuário com os mesmos problemas do standard user, mas dessa vez com o desempenho do site sendo altamente impactado, tornando muito difícil navegar pelas páginas.

No próximo cenário, temos o "error\_user", com o qual conseguimos fazer login normalmente, chegando direto no catálogo como esperado — à parte dos problemas que já notamos com o standard user, como os textos na camiseta vermelha e na mochila. Ao clicar nos filtros e selecionar qualquer uma das opções, o sistema exibe uma mensagem de erro dizendo "Sorting is broken\! This error has been reported to backtrace", o que indica um erro não resolvido que já chegou ao conhecimento dos desenvolvedores. No catálogo, ao tentar adicionar itens ao carrinho, mais uma vez enfrentamos problemas para adicionar a "SauceLabs Bolt T-Shirt", a "SauceLabs Fleece Jacket" e a Red T-Shirt, que novamente exibem o erro visual no nome, "Test.allTheThings() T-Shirt (Red)", e também não podem ser removidas do carrinho — apenas acessando o carrinho e removendo os itens desejados por lá. Indo para o Checkout, mais uma vez é possível preencher os campos First Name e Zip Code com números/caracteres especiais, mas também não é possível digitar nada no campo Last Name — dessa vez nem conseguimos interagir com esse campo. Ainda assim, conseguimos avançar até a página final de Checkout, mas não vamos além disso, já que não conseguimos interagir com o botão finish. Por enquanto, é isso para esse usuário.

Mudando para o "visual\_user", mais uma vez vemos a imagem de cachorro, dessa vez exibida em apenas um item, a "SauceLabs Backpack". Outra coisa que percebemos rapidamente, depois de ver os preços dos itens tantas vezes, é que agora eles aparecem diferentes para esse usuário — à primeira vista, não parece haver nenhum padrão na precificação, com valores totalmente desiguais, exibindo, por exemplo, um preço de $1,26 para a fleece. No catálogo, a função de ordenação ainda funciona, exceto pelo filtro de preço, que continua exibindo os itens em ordem crescente ou decrescente seguindo os preços originais. Um ponto importante é que os preços errados só são visíveis na Home Page/Catálogo — as páginas de produto, carrinho e checkout mostram o preço correto. Também conseguimos adicionar e remover itens do carrinho já na home page, como esperado.

Na aba do carrinho, vemos nosso terceiro bug visual: o botão de checkout aparece no canto superior direito da página, quebrando o padrão criado para essa aba.

As páginas seguintes funcionam exatamente como esperado, com o mesmo erro nas informações de checkout, onde conseguimos preencher os campos First e Last Name com números e o campo Zip Code com letras.
